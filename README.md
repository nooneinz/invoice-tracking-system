# B2B Invoice & Payment Tracking — تحصيل

لوحة مالية لمتابعة فواتير الشركات والدفعات الجزئية والذمم المتأخرة في سلطنة عُمان: إصدار الفواتير بمعاينة مباشرة وPDF عربي، تتبع الاستحقاق، تذكيرات آلية، ومطابقة بنكية، مع وكيلين بالذكاء الاصطناعي. العملة الريال العماني (ر.ع) بثلاث خانات عشرية، وضريبة القيمة المضافة 5%، وتوقيت مسقط.

## المشكلة
تأخر تحصيل الديون بين الشركات، وضياع تتبع الدفعات الجزئية، وغياب تنبيهات آلية للفواتير المتأخرة.

## ما الذي يقدّمه
- **الفواتير:** مسودة ← إصدار ← جزئية ← مسددة (أو ملغاة)، ومعاينة حية بجانب النموذج، وملف PDF عربي مرفق بالبريد.
- **حسابات حتمية:** كل المبالغ أعداد صحيحة بالبيسة (1 ر.ع = 1000 بيسة)، والدفعات داخل معاملة ACID مع `SELECT … FOR UPDATE` على PostgreSQL، ويُرفض الدفع الزائد.
- **التقادم والتحليلات:** أعمار الذمم، المحصّل مقابل المُصدَر، متوسط أيام التحصيل، وأكبر المتأخرين.
- **مهام مجدولة (APScheduler بتوقيت مسقط):** وكيل التحصيل يومياً 08:00، وإرسال التذكيرات المعتمدة كل 10 دقائق، وإعادة المطابقة كل ساعة.
- **Webhook موقّع** (`POST /api/webhooks/payments`) بـ HMAC-SHA256 يستقبل إشعارات أي بوابة دفع ويمنع التكرار بالمرجع.
- **سجل تدقيق** بتجزئة SHA-256 متسلسلة، وأدوار (مشرف، محاسبة وتحصيل، اطلاع فقط) بـ JWT.

## وكلاء الذكاء الاصطناعي
| الوكيل | المهمة |
|---|---|
| **وكيل التحصيل والتذكير** | يولّد تذكيرات قبل الاستحقاق (‎−3‎) ويوم الاستحقاق وبعده (‎+7، +14، +30‎) بنبرة ودّية أو محايدة أو حازمة بحسب سجل كل عميل، عبر البريد أو واتساب (رابط جاهز)، ويقترح خطة تسوية على دفعات للمتأخرات (14 يوماً فأكثر وأكثر من 100 ر.ع)، ويراقب التزام العميل بالخطة. |
| **وكيل المطابقة البنكية** | يقرأ كشف الحساب (CSV)، ويطابق التحويلات بالفواتير المفتوحة: رقم الفاتورة، أو اسم العميل مع المبلغ، أو مجموع عدة فواتير، أو دفعة جزئية. يغلق تلقائياً ما بلغت ثقته 90%+ ويقترح الباقي بسبب مكتوب. |

الرسائل تُحفظ **مسودات** يعتمدها المحاسب، والإرسال التلقائي اختياري للتذكيرات الودية فقط. المنطق الأساسي قواعد صارمة تعمل دائماً؛ ومع `ANTHROPIC_API_KEY` يعيد Claude صياغة النص دون تغيير أي رقم أو تاريخ.

### محادثة الوكلاء
من صفحة **الوكلاء** تسأل كل وكيل بالعربية فيستدعي أدوات النظام (قراءة فقط: الفواتير المتأخرة، تقادم الذمم، كشف حساب عميل، أولويات التحصيل، التذكيرات والخطط المعلّقة، الحركات البنكية غير المطابقة) ويعرض خطواته. بدون مفتاح يفهم موجّه محلي الأسئلة الشائعة.

## ما لا يتضمنه
- **Stripe:** لا يوجد ربط مباشر؛ بدلاً منه webhook عام موقّع يصلح لأي بوابة.
- **SMS:** غير مضمَّن؛ القنوات هي البريد (SMTP) وواتساب برابط جاهز.
- **Redis:** طابور الصادر مخزّن في قاعدة البيانات (جدول `reminders`) ويعالجه المجدول.

## التقنيات
FastAPI · SQLAlchemy · PostgreSQL (SQLite محلياً) · APScheduler · ReportLab + arabic-reshaper (PDF عربي) · React + Vite · Tailwind CSS · Recharts · JWT · Docker.

## التشغيل المحلي
```bash
cd frontend && npm install && npm run build
cd ../backend
python -m venv .venv && .venv/Scripts/activate      # Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
cp ../.env.example .env                              # عدّل ADMIN_PASSWORD و JWT_SECRET
uvicorn app.main:app --port 8002
```
افتح http://127.0.0.1:8002 وسجّل الدخول بحساب المشرف، ثم اضبط بيانات شركتك وحسابك البنكي من **الإعدادات**، وأضف العملاء.

> يتطلب توليد PDF خطاً يدعم العربية؛ يُستخدم Tahoma/Arial على Windows وDejaVu على Linux (مثبّت في صورة Docker).

## التشغيل بـ Docker
```bash
cp .env.example .env   # أضف أيضاً DB_PASSWORD
docker compose up --build
```

## استيراد كشف البنك
ملف CSV بالأعمدة: `date, amount, description, reference, counterparty` — تُستورد الإيداعات فقط وتُتجاهل المكررة.
